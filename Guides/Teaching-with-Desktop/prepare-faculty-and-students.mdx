Use this checklist after completing your [course rollout plan](/Guides/Teaching-with-Desktop/plan-your-course-rollout). The aim is to have faculty, computers, accounts, and student instructions ready for the first scheduled activity.

## Agree who handles each part

One person may fill more than one role. Give each responsibility a named owner in your cohort plan.

| Responsibility | Suggested owner | What they prepare |
| --- | --- | --- |
| Course coordination | Faculty lead | Activity dates, objectives, student expectations, and the review meeting. |
| Teaching and feedback | Teaching faculty | Rehearsed cases, student briefs, image evaluation criteria, and feedback arrangements. |
| Computer readiness | Institutional IT or local technical contact | Installation, device checks, updates, and a route for technical help. |
| Accounts and student communication | Local simulator coordinator | Account arrangements, access instructions, and follow-up on access problems. |

## Check computers and accounts

- Confirm where students will work: institution computers, their own computers, or both.
- Check the [Desktop requirements](/Tech/minimum-requirements-for-running-the-desktop-xray-simulator) and follow the [Desktop setup guide](/Tech/Setup-and-installation-guides/Desktop-X-ray-Simulator-Setup).
- For managed Windows installations, ask IT to review the [MDM deployment guide](/Tech/mdm-deployment-instructions).
- Arrange X-ray Simulator accounts through the institution's coordinator. VitaSim creates and provides these accounts; see [Accounts and Login](/Guides/Introduction/accounts-and-login).
- Confirm the expected student count and account pattern. Licensing is based on students using the simulator, including students who share a station account. Accounts and computers do not determine the license count.
- Test login with internet access available for authentication, as described in the [technical and security FAQ](/Tech/technical-and-security-FAQ).
- Test on representative student computers, using the permissions and login arrangements students will actually have.

If students use their own computers, agree on an alternative access arrangement for anyone whose device cannot run the selected activity. Record that arrangement before assigning independent work.

## Rehearse the complete student workflow

Each instructor should complete the first activity before teaching it.

1. Launch Desktop, log in, and open the exact case students will use.
2. Run the proposed task using the controls available in that case. Check relevant [catalog limitations](/Simulation-Catalog/overview) and note anything students need to know.
3. Prepare the starting image and comparison you will discuss. Use the course's own image evaluation criteria.
4. Follow the student instructions exactly, including exporting an image and submitting it through the intended assignment process if required.
5. Record roughly how long the task takes, where students may need help, and which settings should remain unchanged during comparisons.
6. Agree how to respond to different results and what feedback students will receive.

Use the [Desktop quick start](/Guides/Introduction/getting-started-Desktop-x-ray) for the controls and image export workflow. Keep a copy of your demonstration images available for discussion if a computer needs troubleshooting during class.

## Give students a short access check

Set a deadline before the first teaching activity. Ask students to:

1. Open the Desktop X-ray Simulator and log in using the account instructions provided by the institution.
2. Open the case named by the instructor.
3. If image submission is part of the course, export an image and find the saved file.
4. Report either **ready** or the step where they need help through the agreed course channel.

The coordinator records outstanding issues and follows up with the appropriate contact. The access check confirms that students can start the work; the teaching activity will assess their reasoning.

## Copy and adapt the student announcement

Replace every placeholder before sharing this through your usual course channel. Provide credentials separately through the approved channel.

```text
Subject: Prepare for our first Desktop X-ray Simulator activity

We will use the Desktop X-ray Simulator in [course] on [date] to explore
[topic / learning objective]. The activity will take place [location / format].

Before [access check deadline]:
1. Follow [institution's installation instructions or computer access plan].
2. Use the account instructions provided through [approved channel].
3. Open [case name].
4. [If required: save an image and check that you can find the file.]
5. Report that you are ready, or tell us which step needs help, at [location].

Prepare by reviewing [reading or class material].
During the activity you will [short task].
Submit [expected work] at [submission location] by [deadline].
Feedback will be provided by [instructor / date / method].

For help with the assignment, contact [teaching contact].
For help with computers or access, contact [local technical contact].
If your computer cannot run the activity, contact us before [date] so we
can arrange [institution's alternative access plan].
```

## Be ready for the first session

- Every activity has a named instructor, objective, case, and student brief.
- Faculty have rehearsed the workflow on the version students will use.
- Student access issues have an owner and a participation plan.
- Students know what to prepare, submit, and ask for help with.
- The submission location and feedback date are ready.
- The faculty lead has scheduled the first cohort review.

Start with the [guided first session](/Guides/Teaching-with-Desktop/activities-and-templates#first-session-predict-compare-explain), then use the cohort review to adjust timing and support.

## Route support questions clearly

| Question | First contact |
| --- | --- |
| What does the task mean, or how will it be reviewed? | The course instructor. |
| Can I install the application or use this institution computer? | Institutional IT or the named local technical contact. |
| Which X-ray Simulator account should I use? | The institution's simulator coordinator; see [Accounts and Login](/Guides/Introduction/accounts-and-login) for VitaSim account support. |
| How should the institution count student licenses? | [sales@vitasim.dk](mailto:sales@vitasim.dk). |
| The application does not behave as expected. | The local technical contact or [VitaSim support](/Support/support), with the application version, case, steps, and any error message. |
